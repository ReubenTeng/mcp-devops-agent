# Running the infrastructure MCP server

This package currently runs as a **local stdio MCP process** launched by a chat
client. It is not an HTTP service and cannot be deployed to a static hosting site.
The instructions below run the implemented v2 tools; they do not enable unfinished
providers listed in [implementation status](IMPLEMENTATION_STATUS.md).

## From the repository

Use Node.js 20 or later. From the repository directory:

```sh
npm ci
npm run build
npm test
node dist/index.js doctor --json
```

Doctor checks local paths, permissions and credential presence. It does not test
authentication. Missing optional providers do not prevent local analysis/planning.

## Connect to a chat client

Add this server to the client's MCP configuration, replacing both absolute paths:

```json
{
  "mcpServers": {
    "infrastructure": {
      "command": "/absolute/path/to/node",
      "args": ["/absolute/path/to/mcp-devops-agent/dist/index.js"],
      "env": {
        "MCP_DEVOPS_PROJECT_ROOTS": "[\"/absolute/path/to/your-app\"]",
        "MCP_DEVOPS_STATE_DIR": "/absolute/path/to/private-infrastructure-state"
      }
    }
  }
}
```

Choose a state path outside the app being deployed. The server creates private
state lazily. Keep it between runs for recovery, recorded resources and budgets.
Multiple allowed project roots can be listed in the JSON array.

Add provider keys through the client's private environment/secrets configuration,
or a private `.env` in the server's launch working directory. Do not paste them into
chat, commit them, or put real values in a shared configuration example.

- Vercel: `VERCEL_TOKEN`, `VERCEL_TEAM_ID`; commercial projects require an existing
  Pro team. No automatic subscription upgrade occurs.
- Supabase: `SUPABASE_ACCESS_TOKEN`; supply an existing organization slug and region
  in plan overrides. The requested plan must match the organization's current plan.
- Cloudflare: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`; domain registration
  additionally needs account billing, contacts and agreements already configured.
- GitHub Pages: `GITHUB_TOKEN` with the required repository/Pages administration
  permissions. Supply the existing public repository owner, repo and exact commit
  SHA. This adapter deploys prebuilt committed static content and respects Pages
  commercial-use restrictions.

Only configure the providers you intend to use. Restart/reconnect the MCP server
after changing its process environment.

The client must implement MCP **form elicitation** to display a real human approval
dialog. If it reports `APPROVAL_UNAVAILABLE`, analysis and planning still work, but
mutations remain blocked. There is no approval-bypass setting.

## First conversation

Ask the chat agent:

> Analyze my app, recommend infrastructure within $60/month and $20 upfront, and
> prepare the deployment. Show me missing setup before asking to approve changes.

The agent should analyze, propose, prepare ready steps, request approval for each
execution, then prepare later dependency steps. For Supabase, provide the existing
organization and region when requested. Credentials generated by provisioning move
through private state/local environment writes, with separate approvals.

The package includes `skills/infrastructure-chat/SKILL.md` as an optional guide
for clients that load agent skills. Install/copy that folder into your client's
supported skills directory if you want the reusable chat orchestration workflow.

Use `list_infrastructure_plans` to resume a project. Refresh/reconcile pending or
uncertain steps instead of creating replacement resources. Run
`verify_infrastructure_plan` afterward; an unverified database/health check means
the complete application has not yet been proven to work.

Catalog-only providers need executable adapters installed before execution. API
keys cannot substitute for missing adapter code. Live provider behavior also
depends on token permissions, account eligibility, quotas and billing.

## Install a packaged build

To avoid running from the development checkout:

```sh
npm pack
```

Install the generated tarball into a dedicated local directory:

```sh
npm install /absolute/path/to/mcp-devops-agent-2.0.0.tgz
```

Point the MCP client at that directory's `node_modules/.bin/mcp-devops-agent`, or
use its absolute `node_modules/mcp-devops-agent/dist/index.js` path with Node.
The package is private and has not been published to the npm registry.

## Hosted server status

Remote HTTP/Streamable HTTP transport, multi-user authentication, tenant isolation
and hosted secret storage are not implemented. A shared internet-facing service
requires those features; putting the current stdio process behind a web server
does not provide them.
